Petrobras · BR PAY
Case 02 · Petrobras › BR PAY

Da bomba
ao app. E de volta.

MVP funcional desenvolvido e apresentado no Hackathon Petrobras: fidelidade para postos, pontos em tempo real e divisão de despesas entre passageiros. A versão navegável abaixo reconstrói a experiência para o portfólio.

O problema que ninguém fala

A margem de combustível é baixa, então boa parte do resultado financeiro do posto vem da loja de conveniência. O desafio: poucos clientes chegam a entrar lá. O cliente abastece e vai embora em 3 minutos.

Sem alterar o preço do combustível, é possível melhorar esse resultado com mais visitas e um ticket médio maior na loja. Para isso, um programa de fidelidade efetivo é mais adequado do que um cartão físico pouco utilizado.

A ideia: tornar o abastecimento tão fácil e recompensador que voltar ao posto vire natural, e passar pela loja aconteça sem esforço, aumentando a chance de o cliente levar mais de um item.

Solução em 3 camadas

1. Identificação do veículo: a proposta conecta o veículo à jornada de fidelidade. Nesta versão navegável, chegada e identificação usam dados de exemplo; não há consulta a um carro real.

2. Pontos em tempo real: o fluxo de abastecimento alimenta o cálculo de pontos e a recomendação de produtos. A versão do portfólio reproduz essas etapas com dados de exemplo.

3. Bora Rachar: simula a divisão do custo entre os passageiros informados no app. Os botões de PIX e WhatsApp demonstram a jornada, sem efetuar cobrança real.

Ford Connected API IBM Watson NLU Node-RED MQTT IoT React Native / PWA PIX API WhatsApp API Redis PostgreSQL

⛽ Bora Rachar: App MVP

O projeto teve um MVP funcional no hackathon. Esta versão para o portfólio apresenta seis telas navegáveis da jornada; usa dados de exemplo e não está conectada aos sistemas da Petrobras, de veículos ou de pagamentos.

Como funciona cada camada
🚗
Ford Connected API
No protótipo, o VIN e o evento de chegada são dados de demonstração. O payload mostrado é um contrato didático do projeto, não o contrato oficial de uma API Ford.
⚡
Sensor IoT da bomba
Sensor de pulso na bomba de combustível publica eventos MQTT a cada litro abastecido. O Flow 2 calcula litros × preço e atualiza o app em tempo real via WebSocket.
🔴
Node-RED
Cola de tudo. 3 flows independentes conectados via Link In/Out. Global Context compartilha o estado de sessão entre flows: substituível por Redis em produção.
🤖
Watson NLU
Recebe o histórico de compras na loja como texto. As categorias extraídas viram features para recomendar o item mais provável nessa visita: antes de o usuário entrar na loja.
⭐
Motor de pontos
10 pts por litro abastecido. Calcula saldo em tempo real, verifica rewards disponíveis e dispara push notification com oferta desbloqueada antes de o abastecimento terminar.
🤝
Bora Rachar
Divide o valor simulado pelo número de passageiros informado no app. A tela demonstra o compartilhamento de custos; não detecta ocupantes nem realiza pagamentos reais.
Entendendo o pipeline Node-RED

A arquitetura de referência abaixo explica a jornada do MVP funcional apresentado no hackathon. Os fluxos e trechos de código desta versão foram reconstruídos para o portfólio.

Flow 1: identificação: o exemplo recebe um evento de chegada com um VIN de demonstração. O contrato da mensagem pertence ao exemplo; não pressupõe que a Ford publique esse evento por MQTT.

Flow 2: abastecimento: eventos de volume alimentam o cálculo de valor e pontos. A versão navegável usa valores de exemplo.

Flow 3: recomendação e pontos: organiza o histórico, a recomendação e o fechamento da sessão. Os trechos ilustram a separação de responsabilidades.

MQTT Topics: representam canais de comunicação entre componentes do exemplo. Uma integração real precisa de um conector e de um contrato compatível com cada fonte.

Código Node-RED: nós principais

Nó "Extrai VIN": Function node
// Payload de exemplo do projeto; não é um contrato oficial da Ford
const payload = msg.payload;

msg.vin      = payload.vehicle.vin;
msg.cpf      = payload.user?.cpf || null;
msg.lat      = payload.location.lat;
msg.lon      = payload.location.lon;
msg.stationId = payload.station_id;

// Armazena no contexto global para o Flow 2 sincronizar
global.set('activeVin', msg.vin);
global.set('sessionStart', Date.now());

return msg;
Nó "Litros / R$": Function node
const event = msg.payload; // { type: "pulse", litersPerPulse: 1 }
let ctx = flow.get('fuelSession') || { liters: 0, startTime: Date.now() };

if (event.type === 'pulse') {
  ctx.liters  += event.litersPerPulse || 1;
  ctx.valueR$  = ctx.liters * 6.23;  // preço/litro da bomba
  ctx.points   = Math.floor(ctx.liters * 10);
  flow.set('fuelSession', ctx);
  msg.payload  = ctx;
  msg.topic    = 'fuel/progress';
  return msg; // atualiza app via WebSocket
}

if (event.type === 'stop') {
  ctx.duration = Date.now() - ctx.startTime;
  flow.set('fuelSession', null);
  msg.payload = { ...ctx, vin: global.get('activeVin') };
  msg.topic   = 'fuel/complete';
  return [null, msg]; // saída 2 → dispara Flow 3
}
Nó "Watson NLU": pré-request
const userHistory = msg.userProfile.purchaseHistory;

msg.url     = 'https://api.us-south.natural-language-understanding.watson.cloud.ibm.com/...';
msg.method  = 'POST';
msg.headers = { 'Authorization': 'Bearer ' + env.get('WATSON_TOKEN') };
msg.payload = {
  text: userHistory.map(p => p.item).join(', '), // "café, sanduíche, suco..."
  features: { categories: {}, keywords: { limit: 5 } }
};
return msg;
Nó "Calc pts": Function node
const session  = msg.fuelSession;
const profile  = msg.userProfile;
const pointsEarned = Math.floor(session.liters * 10);
const newBalance   = profile.points + pointsEarned;

const rewards = [
  { id: 'cafe',      pts: 200,  name: 'Café' },
  { id: 'sanduiche', pts: 500,  name: 'Sanduíche' },
  { id: 'pizza',     pts: 800,  name: 'Pizza' },
  { id: 'combo',     pts: 1200, name: 'Combo' },
];

msg.result = {
  pointsEarned,
  newBalance,
  unlocked: rewards.filter(r => r.pts <= newBalance),
  session
};
return msg;
Tópicos MQTT: estrutura completa
ford/vehicle/arrived/{stationId} ← Ford API publica ford/vehicle/departed/{stationId} ← Ford API publica pump/{stationId}/{pumpId}/events ← Sensor IoT publica pump/{stationId}/{pumpId}/status ← Heartbeat do equipamento app/{userId}/notifications ← Node-RED → app app/{userId}/fuel/progress ← Updates em tempo real loja/{stationId}/display ← Node-RED → display da loja
Global Context: como os 3 flows compartilham estado
// Flow 1 escreve:
global.set('session', { vin, userId, stationId, startedAt })

// Flow 2 lê + atualiza:
const s = global.get('session');
global.set('session', { ...s, liters, valueR$, points })

// Flow 3 lê tudo + limpa:
const s = global.get('session');
global.set('session', null); // limpa ao finalizar

Dúvidas técnicas frequentes

A Ford Connected API funciona em qualquer carro?

Não se deve presumir compatibilidade com qualquer veículo. As APIs e os dados disponíveis dependem da oferta do fabricante e da autorização do cliente. A documentação FordConnect prevê acesso com consentimento explícito. Nesta demonstração, chegada e VIN são simulados; não há conexão com um veículo real.

O Bora Rachar realmente sabe quantas pessoas estão no carro?

O MVP funcional permitia demonstrar a divisão de despesas entre passageiros. Nesta versão do portfólio, a quantidade de pessoas é um dado de exemplo, não uma leitura de sensores. O payload ilustrado não é apresentado como contrato oficial da API Ford.

Como o Watson sabe o que recomendar?

O Watson NLU recebe o histórico de itens comprados na loja pelo usuário (texto simples: "café, sanduíche natural, suco de laranja") e extrai categorias de consumo. Esse resultado vira um score de probabilidade para cada item do menu. A recomendação aparece no app antes de o abastecimento terminar: quando o usuário ainda está parado ao lado do carro, mais propenso a entrar na loja.

O PIX funciona sem integração bancária?

Na reconstrução, a geração de um QR Code Pix com pix-payload apenas demonstra a cobrança; não comprova pagamento. Uma implantação real dependeria da integração contratada com o prestador de serviços de pagamento (PSP) do recebedor para confirmar e conciliar a liquidação. Iniciação via Open Finance é uma jornada distinta, com autorização e participante habilitado. Esta demo não movimenta dinheiro nem chama uma API bancária real.

O app funciona em iOS e Android?

O MVP funcionou no hackathon. A versão disponível aqui é uma aplicação web navegável pelo navegador no computador e no celular. Uma distribuição como PWA ou aplicativo nativo exigiria sua própria validação de instalação e compatibilidade.
