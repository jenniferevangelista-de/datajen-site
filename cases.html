Case 01

PolitiCard: Inteligência eleitoral em tempo real

O problema

O eleitor comum não tem tempo nem ferramentas para cruzar dados públicos de candidatos espalhados em portais oficiais, redes sociais e bases judiciais. A assimetria de informação favorece candidatos com histórico opaco.

O PolitiCard propôs reunir informações públicas selecionadas em um único artefato visual, inspirado no formato de carta colecionável.

Cada card exibia partido, estado, cargo, histórico de crimes e condenações, ações legislativas, mandatos exercidos e análise de sentimento NLP das redes sociais com percentual positivo/negativo em tempo real.

Arquitetura de referência · reconstrução

O reconhecimento do hackathon é histórico. Telas, personagens e indicadores são fictícios; esta demonstração não coleta dados de pessoas reais.

A arquitetura em detalhes

① Fontes públicas

Proposta de evolução: conectores por APIs oficiais, sujeitos a acesso autorizado e aos termos de cada fonte. Uma eventual coleta de páginas públicas exigiria avaliação própria; este portfólio não executa scraping nem contorna bloqueios de plataformas.

Dados oficiais: TSE disponibiliza candidaturas em CSV/XML via dadosabertos.tse.jus.br. Portal da Transparência e CNJ (registros de processos) têm endpoints REST documentados. Cruzamento por CPF/CNPJ do candidato como chave primária.

② Coleta & stream

Pipeline em Python com Apache Kafka como message broker: cada fonte publica em um tópico dedicado (social.raw, official.raw). Consumers independentes processam em paralelo sem acoplamento. Isso garante que uma API fora do ar não trava todo o pipeline.

Rate limiting gerenciado por fila de prioridade: dados oficiais (baixa frequência, alta confiabilidade) têm prioridade sobre redes sociais (alta frequência, ruído).

③ Sentimento NLP

Modelo proposto, não executado nesta demo: uma evolução poderia avaliar BERTimbau para classificar sentimento, com testes de qualidade, viés e revisão humana. O limiar 0,65 é um parâmetro ilustrativo, não um resultado validado do MVP histórico.

Agregação por janela deslizante de 7 dias: o percentual no card reflete a percepção recente, não histórica. Possível escalar para análise por tema (saúde, educação, corrupção) com zero-shot classification.

④ Scoring político

Pontuação didática: os pesos e valores das cartas são fictícios. Processos em andamento não demonstram culpa; registros cíveis, ações de improbidade e condenações criminais não devem ser tratados como equivalentes. O score não mede corrupção nem substitui análise das fontes.

Uma implantação exigiria memória de cálculo, origem e data de cada registro, revisão humana, correção de dados e contestação tanto das fontes quanto da pontuação. A fórmula ilustrativa não é uma classificação oficial.

⑤ Base de candidatos

PostgreSQL como source of truth: estrutura relacional porque candidato → mandatos → processos → votos tem cardinalidade bem definida. Redis como cache de leitura para os cards mais acessados (top 1000 candidatos por engajamento), TTL de 10 min para balancear frescor vs. custo de reprocessamento NLP.

Estratégia de cache-aside: miss → busca no Postgres → processa → salva no Redis → serve. Hits esperados de 85%+ em período eleitoral com candidatos sendo buscados repetidamente.

⑥ PolitiCard generator

API FastAPI que recebe o ID do candidato e devolve o JSON completo do card. O frontend (vanilla JS + CSS) renderiza o card em SVG/HTML: portável, embedável em qualquer site de notícias com uma linha de script. Pensado para parceria com portais de jornalismo de dados.

Modo de compartilhamento: card vira imagem OG estática (Puppeteer headless) para ser compartilhado em redes sociais: o eleitor compartilha o card do candidato que está avaliando.

Perguntas técnicas · Como responderia em produção
E quando a API do Twitter cai ou bane o token?

Cada fonte tem um circuit breaker independente (pattern Hystrix). Se a API falha 3x em 60s, o consumer entra em modo degradado: para de tentar, serve os dados do último snapshot válido com timestamp de validade visível no card. O card não some: ele envelhece graciosamente com um indicador de "dados de Xh atrás". Além disso, o score político (dados oficiais) continua funcionando normalmente: que é a informação mais crítica.

O uso de dados públicos dispensa avaliação jurídica?

Não. Dados pessoais públicos continuam sujeitos à LGPD. Uma implantação exigiria avaliar finalidade, base legal, necessidade, termos e permissões de cada fonte, além de atualização, segurança e direitos dos titulares. Respeitar robots.txt e limites de acesso não substitui essa análise. Este portfólio usa personagens fictícios e não oferece garantia de conformidade jurídica.

O modelo NLP não vai ter viés político?

Há risco de viés. Uma evolução real precisaria testar representatividade, qualidade da classificação, ironia, diferenças entre grupos e revisão humana. São requisitos propostos, não testes já comprovados nesta reconstrução. Os percentuais exibidos são fictícios e não indicam a qualidade moral ou jurídica de uma pessoa.

Como escala para todos os candidatos do Brasil (mais de 400 mil em eleições municipais)?

Dimensionamento hipotético, não base processada: 15 mil perfis e uma fila prioritária de 10 mil seriam cenários para testar batch, cache e consumo de APIs. Uma implantação dependeria de benchmark, custos, permissões e validação jurídica; esta demonstração não processou essa população.

Como monetizar isso sem comprometer a credibilidade?

Três modelos possíveis que preservam neutralidade: (1) B2B para portais de notícia: widget embedável via API key, cobrado por volume de cards gerados; (2) licença para aplicativos cívicos (e-Título, apps eleitorais de ONGs); (3) versão premium para pesquisadores com acesso à série histórica e dados brutos. O que não fazer: publicidade segmentada por perfil político do usuário: isso destruiria a confiança e possivelmente a finalidade do produto.
