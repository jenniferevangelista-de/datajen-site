💡 Em linguagem simples
Este é o painel de SRE (Site Reliability Engineering), a prática de cuidar da confiabilidade dos dados como se fossem um produto. Traduzindo os números do topo: MTTR é o tempo médio para colocar um pipeline de volta no ar depois de uma falha (quanto menor, melhor); SLA é a meta de disponibilidade (99,7% significa fora do ar só algumas horas por mês); Pods running são as "caixinhas" de software rodando no Kubernetes; Error budget é a margem de erro permitida antes de estourar a meta; o percentual exibido no topo corresponde ao serviço user-behavior-track no período de 30 dias; SLO e error budget mostra a disponibilidade observada e a margem restante de cada serviço. Fora do horário comercial, entra o plantão (on-call): ficar de prontidão para resolver incidentes seguindo os runbooks (os passo a passo documentados). Simulação didática, sem dados de clientes.
Teste o plantão: provoque a falha e execute o runbook.

O incidente derruba um pod, consome o error budget, abre um alerta e inicia a contagem de MTTR. A recuperação restaura todos os indicadores.

Investigue um incidente de ponta a ponta

1. Simule uma falha. 2. Selecione um pod para ler CPU, memória e reinícios. 3. Execute o runbook e acompanhe a recuperação.
